# 0.3.1 — 2026-11-25

## Added

- **`outcome` input** on `ukcrime_search_crimes` (latest outcome name, or `(not recorded)`) and `ukcrime_search_outcomes` (code or name), ANDed with every other filter and narrowing the counts, breakdowns and page together ([#26](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/26)). A given value is echoed as `outcome`, crimes add `unfiltered_total`, and a value matching nothing returns zero with the values present. A crimes range under the filter still flags a month the area itself returned empty.
- **`street_name_contains` input** on `ukcrime_search_crimes`, `ukcrime_search_outcomes` and `ukcrime_search_stops`, matched locally against the street name with the same narrowing and echo ([#28](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/28)). Words match in any order and by part of a word (`Granby St` finds Granby Street), and the notice names the streets when several match; crimes with `area: 'force_unplaced'` reject it as `invalid_area`.

## Changed

- **Upstream pacing** starts at most 3 requests in any 1000 ms with 4 in flight, where 0.3.0 allowed 15 a second (burst 30). The README, `CLAUDE.md`, `AGENTS.md`, `docs/design.md` and the server instructions state the limit as undocumented and measured.
- **`pacer_shed`** is the reason for a request still queued at its retry deadline, where 0.3.0 reported `retry_deadline_exceeded` for a request that was never sent.
- **`ukcrime_list_reference` `name_contains`** shares the street-name matcher: punctuation splits words and `&` reads as `and`, so `devon and cornwall` finds Devon & Cornwall Police.
- **Known-gaps table** re-verified against its sources and live on 2026-11-25.
- **Vitest** selects the threads pool under Bun, because the 5.1.1 forks pool fails there; `engines.bun` is `>=1.4.4`.

## Fixed

- **Calls stalled about 30 s on data.police.uk 429s** ([#25](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/25)): `ukcrime_get_crime_outcomes` batches, month ranges, `ukcrime_find_neighbourhood` sections and coverage lookups now finish without them.
- **Coverage gaps carry a from-month** ([#27](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/27)): BTP crime since 2025-02 and Gloucestershire crime and outcomes since 2026-02, applied month-aware to searches and listed in `gaps`. The `force_unplaced` zero line no longer states none were recorded for them and keeps the missing-month caveat.
- **Copyable ids** in the `ambiguous_neighbourhood` candidates and the multi-match `unknown_force` ids render as code spans in `content[]`, and a multi-match force is reported before a bad month or category in the same call.
- **`ukcrime_get_crime_outcomes` guidance** reads "Lookups failed for N of these ids" and "This call left N of these ids unprocessed", and the `failed` and `failed[].error` describes cover lookups that were never sent.
- **Avon and Somerset coverage note** states no crime count, since its source says about 2,000 a month and live counts were 705 and 662; it says crime and outcome area searches there undercount, and `ukcrime_search_outcomes` area searches carry it too.
