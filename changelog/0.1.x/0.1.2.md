# 0.1.2 — 2026-10-02

## Added

- **`month_from`** on `ukcrime_search_crimes` and `ukcrime_search_stops` searches up to 12 months ending at `month`: totals, breakdowns and pages cover the range, and `by_month` gives each month's total ([#8](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/8)). New reasons: `invalid_month_range`, `range_too_large`, and retryable `range_incomplete` (fetched months stay cached, so a repeat fetches only the rest).
- **Typed upstream failures on every tool** — `rate_limited`, `pacer_shed`, `upstream_unavailable` and `retry_deadline_exceeded`, each `retryable: true` with a hint naming the wait when one is known ([#4](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/4), [#10](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/10)). A `Retry-After` (seconds or HTTP-date) that leaves time for another attempt is waited out instead of failing the call.
- **Force names** — every `force` input takes a display name such as `Leicestershire Police` or `Devon & Cornwall Police` as well as the id; case, `&` for `and`, and a trailing `Police`, `Police Service` or `Constabulary` are folded, and a name matching two forces fails `unknown_force` naming the candidates ([#7](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/7)).
- **Located forces** — a polygon search locates its bounding-box centre and outermost vertices and reports `area.located_forces`; a location search reports its map point's `located_force` and `located_neighbourhood`; the crime and outcome searches add each found force's coverage notes ([#3](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/3)).
- **Stop flag fields** — `ukcrime_search_stops` filters and breaks down `outcome_linked_to_object_of_search` and `removal_of_more_than_outer_clothing`, as `'true'`, `'false'` or `'(not recorded)'`; a JSON boolean also works ([#6](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/6)).
- **Public hosted endpoint** at `https://uk-police-crime.caseyjhand.com/mcp`, listed as a `streamable-http` remote in `server.json`.

## Changed

- **A persistent 504 is now `upstream_unavailable`** (`ServiceUnavailable`, retryable), like every 5xx or network failure that outlasts the retries; it used to surface as a bare `Timeout` ([#10](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/10)).
- **`force_published`** on `ukcrime_search_stops` is true only when every force found for the area published that month, or every month of a range; `by_month` carries it per month, and the `notice` names each force that skipped, with its months.
- **`ukcrime_find_neighbourhood`** returns every upcoming event the force published, no longer the first 10 ([#5](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/5)).
- **Area cache** grows to 128 MiB and empties when data.police.uk publishes a new month.
- **Tests** — timing checks compare CPU time and unit tests run under a 30 s timeout; `ajv` ^8.20.0 joins the dev dependencies for in-suite JSON Schema checks.

## Fixed

- **`ukcrime_search_outcomes`** gives an uncached month one attempt that runs to the retry deadline, rather than 30 s attempts resent, and a failure there says a repeat search shortly usually succeeds ([#11](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/11)).
- **Zero-hit notices** drop the "try another month" fragment where every force the area falls in publishes nothing of that data, leaving the coverage notes to explain the zero ([#9](https://github.com/cyanheads/uk-police-crime-mcp-server/issues/9)).
